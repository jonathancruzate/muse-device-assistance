# v1.25.0 — screen sharing + takeover (execution record, 2026-11-13)

Jonathan's order (2026-11-13 19:59 EST): "Add screen sharing
streaming to device Assistance app so you can see the screen and
take it over as needed."

Design: `docs/v1.25-screen-sharing-design-2026-11-13.md`.

## What shipped

**Android (v1.25.0, versionCode 36):**
- New module behind Jonathan's in-app switch `screen_enabled`
  (default OFF; MainActivity "Screen sharing (v1.25)" section with
  enable checkbox, status, Start/Stop buttons, and a screenshot
  test button). While off, every action op refuses typed
  `screen_module_disabled`; `screen_status` always answers and
  `screen_stop` is exempt so a stream can never be stranded.
- See, two doors: `screen_shot` (accessibility `takeScreenshot`,
  no per-session consent; config gained `canTakeScreenshot`) and
  `screen_start`/`screen_stop` (MediaProjection stream —
  `ScreenConsentActivity` trampoline shows the system consent
  dialog; `ScreenCaptureService`, mediaProjection FGS with a
  persistent notification + Stop action, long edge ≤720 px,
  ~4 fps JPEG q55, base64-in-JSON frame posts, 10-minute
  auto-stop, fast-input pump ~750 ms). A remote `screen_start`
  can only REQUEST consent: it tries a direct activity launch,
  always posts a tappable "Start screen sharing" notification,
  and its result says `consent_required`. That is a platform
  rule, not a limitation of this build.
- Take over (all through the accessibility service, never shell
  `input`): `screen_tap`, `screen_swipe`, `screen_key`
  (back/home/recents/notifications/quick_settings/lock),
  `screen_text` (SET_TEXT on the focused editable),
  `screen_find_tap` (exact text/content-description match).
  All coordinates are normalized 0..1000 on both axes, scaled
  to real pixels on-device.
- Gates: `ShellAllowlist` native templates; coordinate/key ops
  through shared hygiene; text/label ops through the dedicated
  `checkScreenText` (control-char ban, 256/arg, 1000 total).
  Report gains `shell_bridge.screen` (state only, no frames).

**Relay (all three repo copies + the deployed box relay):**
- `POST /screen/frame` (JPEG magic + 2 MB cap; latest frame as a
  binary store file), `GET /screen/frame.jpg` (raw),
  `GET /screen/meta`, `POST /screen/state`, `POST`/`GET
  /screen/input` (validated, queue cap 50, drain semantics),
  `GET /screen/view` (self-contained viewer: live frame,
  click-to-tap, drag-to-swipe, key buttons, type/find boxes,
  bridge start/stop). A raw-response shape was added to the
  JSON-only plumbing. Report sanitizer gained the `screen`
  whitelist — AND the repo copies were found missing the box's
  v1.21 `self_update` + v1.24 `files` whitelist blocks; those
  were ported back into all three repo copies in this handling,
  so the repo relay is again a strict superset of the deployed
  one (verified by diff: zero box-only lines).
- Muse side driver: `tools/screen.sh`
  (shot/start/stop/status/tap/swipe/key/text/find/fetch/view);
  action ops ride the fast queue while streaming, the bridge
  lane otherwise.
