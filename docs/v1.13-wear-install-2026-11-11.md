## What it adds

The phone half of the Muse Wear Installer lane (project:
`~/workspace/muse-wear-installer/`, DESIGN.md there is canonical):

- **New native command template `wear_install_face`**
  (args: label, https-url, sha256), gated by a dedicated validator
  `ShellAllowlist.checkWearInstall` — the URL can never satisfy the
  shared shell hygiene charset, and these args never become shell
  text, so the validator re-implements hygiene's protections per
  slot (https-only, host required, no userinfo/whitespace/quotes,
  label token charset, exact sha256 shape). `NativeGate` gains an
  additive `String[] args` field (null for all pre-existing ops).
  11 new cases in `tools/ShellAllowlistTest.java` — suite ALL_PASS.
- **`WearInstallRouter`** — downloads the APK over HTTPS with
  streaming SHA-256 verification, picks the connected watch node,
  sends the offer (MessageClient) and streams the APK
  (ChannelClient) to Muse Wear Installer on the watch, then blocks
  (job-keyed latch, BudsRouter pattern) up to 300 s for the watch's
  terminal verdict and returns it as the command result. Stages are
  mirrored to new Store keys `K_WEAR_*` and the bridge log ("WEAR").
- **`WearStatusService`** — a `WearableListenerService` receiving
  the watch's status messages on `/muse-wear-installer/status`.
- **Report:** `wear_install` object (last job id/label/stage/detail/
  at), phone profile only, next to `actuation`.
- **Manifest:** `com.google.android.gms.version` meta-data
  (`@integer/google_play_services_version` = 12451000, new
  `res/values/gms.xml`) + the `WearStatusService` declaration.
- **`WearProtocol.java`** — the wire contract, copied verbatim from
  the watch app's `Protocol.java` (diff-verified identical logic);
  the two copies must change together.

Flow status semantics: the command result is `ok=true` only when
the watch reports `installed`. Failures are typed
(`sha256_mismatch`, `watch_not_connected`, `watch_verify_failed`,
`watch_failed`, `watch_dismissed`, `watch_install_timeout` with the
last stage) — a timeout is never retried automatically.

AndroidX discipline (build-guard amendment, in `app/build.sh`):
defined androidx classes may live only under `androidx.annotation`
+ `androidx.collection` (collection is genuinely used by GMS IPC
internals — ClientSettings / zal / AvailabilityException — and is
vendored as the pure-Java 1.1.0; the 1.4.5 `collection` and 1.9.1
`annotation` jars on Google Maven are Kotlin-multiplatform metadata
with zero Android classes, a trap now documented in both projects).
App classes may reference androidx/annotation only. GMS-internal
dangling references to androidx/{activity,core,fragment} (7 distinct
in this build, all in GMS's error-dialog helpers the Data Layer
never loads) are counted and logged by the guard.

## Build note

The first v1.13 build failed its final guard with
`libconscrypt_jni.so missing from APK` — a false alarm: the .so was
verifiably in the APK. The guard piped `unzip -l` into `grep -q`
under `set -o pipefail`; grep's early exit SIGPIPEd unzip and
pipefail turned the match into a failure. The guard now captures
the listing first, then greps it (same check, no race). Rebuild is
fully green: dex guards, native-lib guards, signature verify.
