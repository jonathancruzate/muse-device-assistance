## What v1.7 adds

v1.6 shipped the push-channel contract (toggles, Store keys,
`PushClient`, the Worker `/device-push` endpoint) with real observers
only for Notifications and Low Battery; Calendar, Contacts, Messages,
Dialer, and Call Log were toggle+permission stubs and Health Connect
was a stub toast. **v1.7 implements the real observers for all six.**
No Worker change was needed — the v1.6 generic sanitizer already
accepts the v1.7 sources.

### New code

- **`PushObservers.java`** — owned by `BridgeService`. ContentObservers
  only mark their channel dirty; the 60-s bridge cycle calls
  `syncDirty()`. Registration is re-evaluated every cycle: toggle OFF
  = unregistered, not read, not pushed; TV profile gated off. A
  missing runtime permission at registration lands in the channel's
  `last_error` + BridgeLog — never a crash.
  - **Calendar** (`phone-calendar`): observer on the Events URI. Query
    `DTSTART >= cursor OR DTEND >= cursor`; items `{id, title, start,
    end, location, all_day}` (the `calendar.search` shape); cap 50 per
    cycle; cursor advances to the sync start only on a 2xx push.
  - **Contacts** (`phone-contacts`): query
    `CONTACT_LAST_UPDATED_TIMESTAMP > cursor`; items `{id,
    display_name, phones, emails}` (comma-joined multi-values, the
    cached-contacts shape); cursor advances to the max timestamp seen,
    only on 2xx.
  - **Messages** (`phone-messages`): observers on the SMS and MMS URIs
    with **separate row-id cursors** (Store keys
    `push_messages_sms_id` / `push_messages_mms_id`); query
    `_ID > cursor`; items `{id, kind, address, body, date, type,
    read}` (the `message.search` shape). An MMS-leg failure is isolated
    from the SMS leg.
  - **Call Log** (`phone-calllog`): query `_ID > cursor` (Store key
    `push_call_log_id`); items `{id, number, type, date, duration,
    cached_name}` (the `call_log.search` shape).
  - **Dialer** (`phone-dialer`): a `TelephonyCallback.CallStateListener`
    registered **only while the channel is ON**; live events pushed via
    `PushClient.pushAsync` as `{state, state_code, number, ts}`.
    **Platform limit (found in build):** the API-35 framework listener
    delivers the state int only — no number — so events currently carry
    `number:""`. The field is present for the day a lane exposes it.
  - First observer run for the id-cursor channels **seeds the cursor to
    the current max `_ID`** — no historical dump, per the design rule.
- **`HealthPush.java`** — **LIVE, not stubbed.** Feasibility resolved
  in build: the android-35 platform jar already contains the framework
  Health Connect API (`android.health.connect.HealthConnectManager`,
  change-log token APIs), so **no new dependency** was needed. One
  change-log token covers Sleep / Steps / HeartRate / Exercise;
  checked from the BridgeService cycle, throttled to 15 min. The first
  check seeds the token (no historical dump). Upserted records push as
  `phone-health` items `{record_id, type, start_time, end_time}` plus
  per-type fields (count; stages + title; samples + bpm_first;
  exercise_type + title). The next token is stored **only on a 2xx
  push** (or when there were no records). With no HC permissions
  granted, the check sets the channel `last_error` loudly (see
  verification below) instead of pretending.
- **Store.java**: new keys `push_messages_sms_id`,
  `push_messages_mms_id`, `push_call_log_id`, `push_health_token`,
  `push_health_last_check`.
- **BridgeService.java**: creates `PushObservers` on its handler thread
  in `onCreate`, stops it in `onDestroy`; the cycle calls
  `pushObservers.syncDirty()` + `HealthPush.check(this)`.
- **AndroidManifest.xml**: added `android.permission.health.READ_SLEEP
  / READ_STEPS / READ_HEART_RATE / READ_EXERCISE`.
- **MainActivity.java**: channel hint texts updated ("Live since
  v1.7: …"); health toast updated.
- **app/build.sh**: `VERSION_CODE=16`, `VERSION_NAME="1.7.0"`.

Universal rules honored: cursor advances only on PushClient 2xx;
every observer failure lands in the channel `last_error` + BridgeLog;
toggle OFF = unregistered / not read / not pushed.
