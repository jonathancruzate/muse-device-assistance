# v1.23.0 — Phase 2 actuation removal (2026-11-13)

**Version:** 1.23.0 (versionCode 34), up from 1.22.0 (code 33).
**Trigger:** On the night of 2026-11-12/13, the app's armed Phase 2
actuation fired the same Samsung "Switch … mode" routines that
mode-sync.sh fires, seconds apart on the same desired write — two
toggles cancel out, and Sleep failed four nights running while each
side's logs looked locally sane. Jonathan disarmed actuation in-app,
verified Sleep holding under mode-sync.sh alone, and ordered the
machinery **removed from the app**. mode-sync.sh is now the only
phone-mode writer — by construction, not by gate state.

## Removed

Applied identically to both source trees (`app/` and
`github-export/app/`; the trees were diff-verified identical before
and after the change).

- **`Actuation.java` — deleted** (337 lines): the whole Phase 2
  decision/fire engine (gate evaluation, Away-latch clear sequencing,
  per-seq fire markers, shadow-evidence + history records, the report
  snapshot).
- **`RoutineFirer.java` — deleted** (87 lines): the capture-based
  routine firer (CREATE_SHORTCUT link intents, `fire`, `isLinked`,
  `linkedName`, link-key mapping into Store).
- **`BridgeService.java`**
  - The `Actuation.cycle(this, v)` call in the reconcile loop is gone;
    the loop is now: fetch desired → `Reconciler.evaluate` → push
    channels → report, exactly as before minus actuation.
  - Header comment rewritten: the service is shadow **permanently** —
    it observes, verifies, plans, and reports; it NEVER fires.
  - `updateNotification` no longer reads the arm state; the status
    notification always reads "(shadow — observing only)".
- **`WorkerClient.java`** — the report no longer carries an
  `actuation` object (`Actuation.snapshot(ctx)` call + its comment
  block removed). Every other report field is unchanged.
- **`MainActivity.java`**
  - The entire "Phase 2 actuation" UI section is gone: section label,
    hint text, status view, the ARM checkbox + its listener, the four
    per-mode "Link routine" buttons, and the "Test fire: Night
    routine" button.
  - `startLink(...)` and the link-flow `onActivityResult(...)`
    (request codes 61–64, the only consumer of
    `startActivityForResult`) removed — no dangling handlers.
  - The `actView` / `armCheck` fields and the "Actuation armed: … /
    Linked …: … / Last fired seq: …" status block in `refresh()`
    removed.
  - Header subtitle now reads: shadow by design — the bridge observes
    and reports only; it never fires routines.
- **`Store.java`** — the actuation key block removed: `K_ACT_*`
  (armed, fired-seq/at/gt, last-log, away-clear seq/at/gt, shadow,
  last-fire, history) **and** the actuation-only `K_LINK_*` /
  `K_LINK_NAME_*` routine-link keys (their only consumers were
  `RoutineFirer` / `Actuation` / the removed UI). No unrelated keys
  touched. Existing on-device prefs under the removed keys are simply
  orphaned — nothing reads them, and the stored link intents/arm flag
  are inert.
- **`build.sh`** (both trees) — `VERSION_CODE` 33 → 34,
  `VERSION_NAME` "1.22.0" → "1.23.0".

**Not modified:** `Reconciler.java` — observe-only by design ("It
NEVER fires"); it computes verdicts/plans and still never actuates.

## What remains intact

- The 60-second reconcile loop: desired fetch, ground-truth parse,
  drift verdict + shadow plan, change/heartbeat reporting to the
  Worker, transport probation/revert, ADB bridge, Tailscale guard,
  shell bridge, push channels, wear-install routing, local channel,
  self-update — all unchanged.
- Reports keep every field they had except `actuation`.
