## What v1.9 does (one feature)

The app reads its Worker base URL + secret from Store prefs
(`base_url` / `secret`, entered on-device). A new local relay will
replace the Worker. v1.9 lets the app migrate itself with **no
on-device step**: the old base hands it the new base inside a normal
mode-state response, the app probes the new base before switching,
and a 24 h probation fallback reverts it if the new base proves
unreachable.

### The switch (`WorkerClient.fetchDesired` → `handleTransportDirective`)

After a successful desired parse (non-TV path only — `fetchDesired`
already returns false on TV, so the Shield never migrates), the
response's optional top-level `transport` object
`{"base": "...", "secret": "..."}` is handled:

- Absent, or `base` equals the current `K_BASE_URL` → nothing.
- Validation: base non-empty and starting with `http://100.`
  (tailnet) or `https://`; secret non-empty, length ≥ 16. Invalid →
  BridgeLog `TRANSPORT directive invalid, ignored`; the cycle
  continues on the current base.
- **Probe before switching:** `GET {transport.base}/mode-state?secret={transport.secret}`
  with the same 10 s connect/read timeouts as every other call;
  requires HTTP 200 and a parseable JSON body containing `desired`.
  Probe failure → BridgeLog `TRANSPORT probe failed, staying on
  current base`; no switch, and no retry loop — the next cycle's
  `fetchDesired` sees the directive again naturally.
- On probe success: the current base/secret are saved to the PREV
  keys, the new pair is persisted to `K_BASE_URL` / `K_SECRET`,
  `K_TRANSPORT_SWITCHED_AT = now`,
  `K_TRANSPORT_PROBATION_UNTIL = now + 24 h`, BridgeLog
  `TRANSPORT switched to local relay base <base>` (the base URL is
  logged — a tailnet IP, not a credential; **neither secret value is
  ever logged**).
- `fetchDesired` returns the desired values it already parsed from
  the old base's response — that payload stays valid: the directive
  rides the old base's response and the new base is seeded with the
  same desired state.

### Probation fallback (`BridgeService.cycle` → `WorkerClient.maybeRevertTransport`)

The cycle now tracks three local booleans: `fetchOk` (this cycle's
`fetchDesired` result), `reportAttempted`, `reportOk`. **After** the
normal desired fetch + report attempt — immediately after the
report block, before `updateNotification` — the probation evaluation
runs once per cycle, only when the cycle is configured, non-TV, the
fetch failed, a report was attempted, and the report failed:

- If `now < K_TRANSPORT_PROBATION_UNTIL` and the PREV keys are
  non-empty, probe the PREV base once
  (`GET {prev}/mode-state?secret={prevsecret}`). HTTP 200 + a body
  carrying `desired` → restore `K_BASE_URL` / `K_SECRET` from PREV,
  clear `K_TRANSPORT_SWITCHED_AT` and `K_TRANSPORT_PROBATION_UNTIL`
  (the PREV values themselves are kept), BridgeLog
  `TRANSPORT reverted to previous base (local relay unreachable)`.
- If the prev probe also fails → stay on the new base; the in-prefs
  push queue already absorbs outages.
- After probation expiry: no probing, no revert — the PREV values
  remain stored but inert.

Note the report attempt is conditional in the cycle's existing
design (change or 15-min heartbeat), so a cycle with a failed fetch
but no report due does not evaluate probation that cycle; the next
report-bearing cycle does.

### What did NOT change

- **No component caches base/secret (verified in sources):**
  `WorkerClient` (fetchDesired / postReport / fetchCommand /
  postCommandResult), and `PushClient.pushPayload` all read
  `Store.K_BASE_URL` / `K_SECRET` at call time. A switch therefore
  takes effect on the very next call of every channel with no code
  change to PushClient, postReport, or fetchCommand.
- Per-channel push toggles untouched; cursors still advance only on
  2xx; failures still land in channel `last_error` + BridgeLog.
- No new permissions, no manifest changes, no allowlist changes.

- **`Store.java`** — four keys: `K_BASE_URL_PREV` (`base_url_prev`),
  `K_SECRET_PREV` (`secret_prev`), `K_TRANSPORT_SWITCHED_AT`
  (`transport_switched_at`, long), `K_TRANSPORT_PROBATION_UNTIL`
  (`transport_probation_until`, long).
- **`WorkerClient.java`** — `fetchDesired` calls
  `handleTransportDirective(ctx, root, base, secret)` after the
  desired store, still returning true with the just-parsed desired;
  new `handleTransportDirective` (validate → probe → persist),
  `probeModeState` (shared probe: HTTP 200 + body carrying
  `desired`, 10 s timeouts), and public `maybeRevertTransport`
  (the probation revert). Class javadoc notes the v1.9 directive.
- **`BridgeService.java`** — cycle tracks `fetchOk` /
  `reportAttempted` / `reportOk` as locals; after the report block,
  `if (configured && !tv && !fetchOk && reportAttempted && !reportOk)`
  calls `WorkerClient.maybeRevertTransport(this)`.
