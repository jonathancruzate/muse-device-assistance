# v1.24 — Phone file management (2026-11-13)

**Trigger:** Jonathan, 2026-11-11 20:02 EST — "I mean local files on
my phone such as the downloads folder." Verification the same night
showed phone local files had **zero coverage**: the Galaxy S24+'s 43
paired-device commands include no file command, the Device
Assistance shell bridge's allowlist had no file template, the app
reported only total/free storage, and no automation anywhere
touched phone Downloads. He chose "Build phone file management
into Device Assistance" (options widget, answered 2026-11-13).

## Design

### Why native ops, not shell templates

Real download names carry spaces and punctuation that the shell
bridge's shared `hygiene()` bans by design (argv is space-joined).
File work never needs a shell: the new ops are **native templates**
(the flashlight / buds / wear / self_update pattern), gated by a
dedicated validator in `ShellAllowlist.checkFiles` and executed by
`FileRouter` via `java.io.File`. Values are typed, never shell text:

- **Folder slots are tokens**, code-mapped in `FilePlan` to the
  public shared-storage folders: `download`, `documents`, `dcim`,
  `pictures`, `movies`, `music`. A command can never name a path.
- **File-name slots are word args joined with single spaces** (the
  v1.14 `voice_bridge` pattern), then validated by
  `FilePlan.nameOk`: direct children only — no separators, no
  parent references, no dotfiles, no control characters,
  ≤255 chars. Organized-category tables and the trash root also
  live in `FilePlan`, which is pure Java so the gate suite tests
  the filing rules on a JVM (`tools/ShellAllowlistTest.java`).

### Commands (all ride the existing Worker command channel and the
v1.20 local channel unchanged — one gate, one executor)

| template | args | result |
|---|---|---|
| `files_access` | — | All-Files-Access state + per-folder exists/readable; the only op allowed without the grant |
| `files_summary` | — | per-folder recursive files/dirs/bytes/newest (scan capped at 4,000 entries/folder, cap flagged) |
| `files_list` | `<folder> [offset]` | direct children, newest first, page of 40; `F\|D / size / mtime / name` lines |
| `files_hash` | `<folder> <name…>` | streaming SHA-256 (≤1 GB), size, name |
| `files_move` | `<folder> <dest-folder> <name…>` | rename between public folders, size-verified, never overwrites |
| `files_trash` | `<folder> <name…>` | MOVE to `/storage/emulated/0/.muse-trash/<folder>/` + ledger line; collision gets a ` (2)` suffix |
| `files_organize` | `<folder>` | files loose direct children by extension category; download/documents only |

Output is capped at 12,000 chars in the router (channel tail bound
is 16 KB). Every op records `K_FILES_LAST_OP/AT/DETAIL` and the
bridge report gains `shell_bridge.files = {access_granted,
last_op, last_detail, last_at}` (state only, never file names).

### Access model — the grant IS the switch

Android scoped storage means no honest inventory exists without
**All Files Access** (`MANAGE_EXTERNAL_STORAGE`, checked via
`Environment.isExternalStorageManager()`). There is deliberately
no partial MediaStore fallback — a scoped view would silently
under-report the phone, the exact failure this feature exists to
fix. The manifest declares the permission; it is a special app
access granted **once by Jonathan** (in-app *Phone files* section →
"Grant All Files Access", or Settings). Until granted, every op
except `files_access` refuses typed `files_access_not_granted` —
the same armed-by-his-act pattern as the voice module. No extra
Store toggle: the system grant is the single writer for this
capability.

### Safety rules (his standing file-cleanup rules, carried over)

- **Nothing is ever permanently deleted.** There is no delete
  template; trash is a recoverable move with a ledger
  (`.muse-trash/ledger.txt`), restorable via `files_move` back.
- **Moves never overwrite.** Collision = skip (organize) or typed
  refusal (move); every move is size-verified after rename.
- **Organize is conservative:** direct children only, extension
  must have a category (Images / Documents / Archives / APKs /
  Audio / Video subfolders of the same folder), files younger
  than 1 hour are never touched (in-progress downloads), dotfiles
  and `crdownload/part/tmp` never filed, cap 100 moves per run.
- Media library folders (dcim/pictures/movies/music) are list /
  hash / move / trash only — organize refuses them; they are
  app-managed libraries, not download piles.

## UI

MainActivity gains a **Phone files (v1.24)** section directly
under the shell bridge section: what the capability is, live
grant state + last-op line (`FileRouter.uiState`), the grant
button (deep link to `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`
for this package, generic page as fallback), and an "Inventory
Downloads now" button that runs `files_list download 0` on-device.

## Verification bar

Gate suite ALL_PASS (incl. ~30 new v1.24 cases) → full `build.sh`
pass with all dex/native guards → apksigner verify, family cert
unchanged → install via the v1.21 `self_update` lane (long-TTL
enqueue; the phone was not fetching commands at build time, so the
update lands on its next fetch cycle) → post-install, fresh-timestamp
read-back: report `shell_bridge.self_update.version_name = 1.24.0`
and a `files_access` command result executed by the new build.
Full inventory (`files_list download`) goes live the moment
Jonathan makes the one-time All Files Access grant.
